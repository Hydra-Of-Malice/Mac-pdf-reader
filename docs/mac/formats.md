# macOS port: document formats

How each format reaches an engine on macOS, what it needs, and whether it works. "Supported" means a representative
fixture opened, rendered and (where it has text) was searched through `src/mac/SumatraMacEngine.h` in a recorded run
of `tests/mac/run-engine-tests.ts`. A registered file extension alone is not support.

The Cocoa app opens files through `MacOpenDocument()` → `ReaderModel::Create()` (`src/ReaderModel.cpp`), not through
Windows' `CreateEngineFromFile()` (`src/EngineCreate.cpp`). `ReaderModel` picks the engine from the file extension
only: DjVu → `EngineDjvuDec`, images → `EngineImage`, CBZ/CBR/CB7/CBT → `EngineCbx`, LIT → LIT-to-EPUB + MuPDF,
everything in `IsEngineMupdfSupportedFileType()` → `EngineMupdf`. There is no content-sniffing fallback, and the
ebook engines in `src/EngineEbook.cpp` (MOBI, CHM, PalmDoc, HTML, TXT on Windows) are not built: they lay out and draw
text with GDI+ (`Gdiplus::Graphics`, `mui` fonts), which does not exist on macOS.

## Fixtures and tests

- Fixtures: `tests/mac/fixtures/` (generator: `tests/mac/make-fixtures.ts` + `tests/mac/fixture-lib.ts`), plus
  existing repo fixtures referenced by path. Expectations: `tests/mac/fixtures/manifest.json`.
- Driver: `src/tools/test_mac_engine.cpp` uses only `src/mac/SumatraMacEngine.h` (like `SumatraMac.mm`): open
  (passwords via `MacSetPasswordCallback`), page sizes, layout, sync + async render, find, selection, TOC, link
  hit-testing, properties, close while renders are pending.
- Runner: `bun tests/mac/run-engine-tests.ts --driver <test_mac_engine>` — per-file timeout, per-format table.
